`initialize` has no arguments. It verifies the upgrade authority through ProgramData, creates Store and receive-types accounts, and registers the Store with the real Endpoint. Accounts are administrator signer/writable, executable transport, ProgramData, writable Store, writable receive-types, System program, followed by official register-OApp CPI accounts. `initialize_peer` creates a peer once with `(domain:u32, eid:u32, router[32])`; accounts are administrator signer/writable, writable Store, writable Peer PDA and System program. Peer seeds are `Peer, Store, eid:u32BE`. All three canonical global peers must exist before `seal_route` can move the Endpoint delegate to the Store. There is no peer or configuration replacement instruction after sealing.

`quote(domain:u32, sequence:u64, options:Vec<u8>)` takes Store, Peer, Goal and official Endpoint quote CPI accounts. `send(domain:u32, sequence:u64, native_fee:u64, options:Vec<u8>)` additionally takes a payer signer before Store. Sequence zero derives a REGISTER from actual goal metadata. Positive sequences reconstruct actual PREPARE, ABORT or COMMIT state for the selected participant; callers cannot supply arbitrary amounts. Sending a PREPARE predecessor remains possible during abort/achievement for delivery recovery.

Incoming handlers authenticate source EID, router peer, domain, participant vault/owner and configuration leaf before calling Endpoint `clear`. The core update then uses the per-goal receiver PDA signer.
